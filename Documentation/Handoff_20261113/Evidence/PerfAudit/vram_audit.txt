Priority candidates (measure and visually validate, not automatically endorsed):
1. r.Shadow.Virtual.MaxPhysicalPages 4096 -> 2048
   High preset uses 2048. PhysicalPagePool is R32_UINT with two array slices;
   static/dynamic count is always 2 in UE5.8 GetTotalAllocatedPhysicalPages().
   Two retained world pools together should save about 512 MB, plus ~85.4 MB HZB.
   ResolutionLodBiasLocal +1 halves local shadow resolution and can reduce page
   demand if 2048 overflows. Do not accept missing shadows/page overflow.
2. r.LumenScene.SurfaceCache.AtlasSize 4096 -> 3072 or 2048
   Runtime configurable, detects size change and reallocates scene atlas.
   2048 means 75% fewer atlas texels. The small floor may fit, but verify
   oversubscribed warning, GI coverage and appearance before persistence.
3. r.Lumen.ScreenProbeGather.RadianceCache.ProbeResolution 32 -> 16
   High preset value. Runtime configurable; reduces rays per probe and atlas
   resolution. Existing large atlas sets predict about 248 MB saving across
   both sets. Avoid reducing ProbeAtlasResolutionInProbes just to save memory:
   source explicitly warns overflow currently causes incorrect rendering.
4. r.Nanite.Streaming.StreamingPoolSize 512 -> 128
   Runtime configurable, excludes roots. Default ReservedResources=0.
   Capture CsvCategory NaniteStreamingDetail enable first if needed:
     NaniteStreamingDetail/StreamingPoolSizeMB
     NaniteStreamingDetail/VisibleStreamingDataSizeMB
   Compare against used size and streaming stability. Restore category disabled.
   Root allocation only 16 MB, not a meaningful target.

RT disabling/restart:
r.Lumen.HardwareRayTracing 0 only selects software Lumen; it is not the global RT
resource-release switch, and other consumers/caches can remain.
r.RayTracing itself is ECVF_ReadOnly: permanent project-wide 0 requires restart.
UE5.8 default r.RayTracing.EnableOnDemand=1 (also ReadOnly).
When that is enabled, r.RayTracing.Enable 0 is runtime mutable.
RayTracingGeometryManager.cpp1006-1019 calls EvictAllGeometries on transition and
asserts TotalResidentSize==0. Thus BLAS eviction need not require restart.
This does not prove every driver/RT allocation is immediately released.
Since measured geometry residency is only 17.6 MB, RT geometry memory is not the
main observed 0.7 GB over-budget cause. RT performance may still merit A/B.

Avoid:
- r.RenderTargetPoolMin reduction as a substitute for resizing live buffers.
  It only evicts unused render targets; nearly all current entries are in use.
- Texture streaming pool increase to conceal the physical VRAM overage.
- Assuming a runtime A/B updates dormant Editor-owned view-state allocations.
  A later Editor redraw or fresh PIE is needed to verify both sets resize.
- Comparing a packaged game without Editor to Editor+PIE as the same memory test.
