Escape From KD　正式展示版の暖機後232フレームの調査
2026年11月17日　職場PC・KDStage

対象と測り方
Core i7-12700H、GeForce RTX 3050 Laptop GPU（4 GiB）、AC給電。Unreal Editorを起動したまま、独立したWindowsデスクトップでShipping版のプレイヤー You を歩かせた。ユーザーの入力先を切り替えず、実習室の中央から廊下を経由して下り階段の最初の踊り場まで8地点を通過した。表示1920×1080、内部解像度54%、TSR履歴100%、VSyncオフ、フレーム上限なし。通常の照明は影あり42灯がMegaLights、補助光19灯が従来方式。実習室の影用設定と接地影を比較の基準とした。
各起動の1周目を暖機として除外し、以降の実移動中だけを集計した。1フレームはゲームの主スワップチェーンの連続するPresent開始時刻の間隔。60 FPSの予算は1000/60 ms、P99は全対象フレームを短い順に並べた上位1%の境界（nearest rank）。平均FPSは1000÷平均間隔。入力先を保持したため、ディスプレイに実際に表示されたフレームの間隔は測定対象外。

以前の正式展示版の232件
ReleaseAとReleaseBの暖機後各10周、計14,310フレーム。232件（1.62%）が予算を超えた。P99は17.3892 ms、最大22.7703 ms。

実習室中央と出口は20周すべてで超過した。両区間で件数の80.17%、時間予算を超えた分の86.88%（275.18 / 316.72 ms）を占める。出口へ向けて曲がった後、進行方向の1～2 mは39 / 220件（17.73%）。各地点・向きを揃えた他周の予算内フレームと比べると、元の232件で提出間隔の差は中央値4.65 msだった。超過中の先頭Present呼び出し自体は中央値0.47 ms、最大1.35 ms。

同時診断から分かった時間の内訳
・同じクック内容の診断Shippingで暖機40周・28,824フレームを照合。エディタが同じGPUの3Dキューに仕事を投入する周期は約333 msだった。エディタの仕事が未完了の時間と重なったフレームは276 / 2,576（10.71%）が超過し、重なりのないフレームは189 / 26,248（0.72%）。各フレーム先頭3 msだけで判定しても16.95%対0.80%。周期を半分ずらすと同じ関連は消える。元の正式版でも、前半で決めた周期の位相を後半10周に当てると10.71%対0.70%になった。未完了時間にはキュー待ちも含まれる。元の232件それぞれについてエディタがGPUを使った時間は残っていない。
・別途、同一コースのDevelopment版をUnreal Insightsで計測し、場所と向きの近い別周の通常フレームと比較した。実習室中央の遅い提出フレーム76組ではゲームスレッドの描画同期待ちを含むアイドルが平均4.21 ms長く、出口114組では2.63 ms長かった。ゲーム側の処理が重くなる地点はエディタの周期外にも残る。
・独立に判定した中央通路の遅いGPUフレーム50組では、Lumenの間接光（ScreenProbeGather）が平均1.18 ms、ShadowDepthsが0.93 ms（内側の仮想影は0.79 ms）、MegaLightsが0.54 ms長かった。出口の旋回後1～2 mの遅いGPUフレーム10組ではLumenが0.90 ms、BasePassが0.74 ms長かった。これらは処理開始から終了までの差で、同時実行や親子関係があるため合算できない。

単独の変更候補を比較した実走
通常版と候補を前後で入れ替え、それぞれ独立した2起動、暖機後計20周を比較した。通過したフレームの総数は歩行速度、フレーム時間により異なる。別の時刻に取った通常版の数値は候補ごとに示す。
・ゲームのWindows GPUスケジューリング優先度を通常（2）から高（3）へ変更。通常206 / 14,504、P99 17.1860 msから、候補227 / 14,533、17.2362 ms。超過が21件増えた。
・実習室の机と椅子の影専用メッシュをそれぞれ4区画に分割。通常259 / 14,481、17.4579 msから、候補235 / 14,367、17.5317 ms。超過は24件減少したもののP99が0.0738 ms悪化した。1組目は超過が6件増、2組目は30件減と向きも揃わなかった。机・椅子の影の三角形、法線、マテリアルを維持し、1,472本の衝突確認が一致。固定露出で机脚と車輪の影を確認した。6箇所の8×8平均RGB画素差は0.2342 / 255で、通常版の再撮影の差は0.2017 / 255。
・エディタを最小化する試験は2回とも途中で元の表示状態に戻った。完全に最小化を保てた周回は2周だけで、この試行を採否に使用していない。

エディタ優先度とLumenを個別に試した暖機10周
順に通常、エディタGPU優先度だけ変更、Lumenだけ変更、通常と実行。各行とも全11周中の2～11周を採用した。

どちらの候補も前後両方の通常測定より超過率・P99が悪化した。前後の通常20周合計は185 / 14,638（1.2638%）、P99 17.0882 ms。同じ正式版の条件間の揺れであり、最初の232件から47件改善したという意味にはならない。
エディタ優先度の試験ではゲームのGPU優先度を通常に保ち、116サンプルでエディタの優先度0を確認。ゲーム終了時に元の2に戻った。前対照の試行名はEditorIdleB1だが、監視用ハンドルの権限不足で優先度設定に到達しなかった。途中で両プロセスの通常値2を別読出しで確認した。
Lumenの比較版は本体pakのWindowsEngine.iniで r.Lumen.DiffuseIndirect.AsyncCompute のみ1から0へ変更。他1,772エントリの内容・圧縮方式、Shipping実行ファイル、IoStoreの内容が一致。実GPUの同一コンテナを使った撮影で実効値0と全体の r.Lumen.AsyncCompute=1 を確認した。固定露出の接地6領域の差は0.1859 / 255、同一内容の再撮は0.2017 / 255。机脚とキャスターの影の輪郭も確認した。追加pakだけを使った初期試行ではゲーム内の実効値が1のままで、変更の効果の集計から除外した。

GPUの余裕を増やすため、80 FPS上限を単独で試した結果
通常版は歩行中のGPU負荷中央値が99%だった。ゲームユーザー設定の FrameRateLimit だけを0から80に変更した比較版を同一経路で11周走らせ、Shipping実行ファイルが開始時と終了時に t.MaxFPS=80 を記録した。初回にWindowsEngine.iniの値だけを変えた試行は実効値が0で、この比較から除外した。
暖機10周では、直前の通常87 / 7,298（1.1921%）、P99 16.8649 msから、候補117 / 6,570（1.7808%）、17.9962 ms。GPU負荷中央値は99%から94%へ下がったが、実習室中央で44 → 48件、出口で22 → 35件に増加。移動合計84.79 → 84.61秒、通過点80箇所の位置差中央値2.33 cm。上限を設定して母数が減っても超過件数、超過率、P99のすべてが悪化した。ゲームGPU優先度の補助読取りは最終周の到着から2.71秒後、プロセス終了時のD3D破棄中に失敗した。読取りによる設定変更はなく、歩行・Present記録・ゲームの正常終了を確認した。

採否と現行の配布版
画質・接地影を維持する条件で、超過件数とP99の両方を繰り返し改善した候補は今回0件。正式展示版の変更は見送り、下り階段までの全フレーム60 FPSは未達。正式配布元は Saved/ExhibitBuild_20261117_ExitCull/Windows、ゲーム本体 myProject-Win64-Shipping.exe のSHA-256は EC99CEF10D90F3E3F7305CE059440284F763FD316F26221630492DA2506CC5BF。
